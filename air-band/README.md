# Air Band — 2단계 (한 손 드럼 · 방향으로 드럼 고르기)

스틱(센서)을 휘두르면 브라우저에서 드럼 소리가 나는 데모입니다.
**2단계**부터는 IMU(가속도 + 자이로)로 스틱 방향을 추정해서, **타격 순간 스틱이 가리키는 방향**으로 드럼을 고릅니다.
정면은 스네어, 왼쪽은 하이햇, 오른쪽은 탐, 위로 들면 크래시입니다 (아래 "5. 2단계: 방향으로 드럼 고르기").
IMU가 없어도 **보드 버튼 1~4로 드럼 4개(스네어/킥/하이햇/탐)** 를 칠 수 있습니다 (아래 "버튼 드럼 모드").

```
[NU40 DK + 6축 IMU] --BLE(NUS)--> [브라우저 웹앱: Web Bluetooth → Web Audio → Canvas]
```

```
air-band/
├ firmware/air_band_right/air_band_right.ino   누코드 펌웨어
├ firmware/air_band_right/orientation.h        스틱 방향 추정 · 구역 판정 (순수 계산, PC에서도 컴파일 가능)
├ web/                                         웹앱 (TypeScript + Vite, 프레임워크 없음)
├ docs/blog-air-band-poc.md                    블로그 글 (스크린샷: docs/images/)
├ docs/slides.html                             발표 자료 (reveal.js, 브라우저로 열기)
└ README.md
```

## 1. 배선 (IMU ↔ NU40 DK)

| IMU 핀 | NU40 DK | 비고 |
|---|---|---|
| VCC / VIN | 3V3 | IMU 모듈이 3.3V를 지원하는지 확인 (5V 전용 모듈 금지) |
| GND | GND | |
| SDA | **P0.26** | BSP 기본 `PIN_WIRE_SDA` |
| SCL | **P0.27** | BSP 기본 `PIN_WIRE_SCL` |
| AD0 / SA0 | 아래 "I2C 주소" 참고 | |
| INT | (미사용) | 1단계는 폴링 방식 |

- P0.26 / P0.27은 누코드 BSP의 `variants/nu40dk_nrf52840/variant.h`에 정의된 기본 I2C 핀입니다.
  **TODO: 확인 필요 — 보드 헤더에서 P0.26, P0.27이 실제로 어느 핀인지는 NU40 DK 핀맵/실크로 확인하세요.**
- 다른 핀에 연결했다면 `air_band_right.ino` 상단의 `PIN_IMU_SDA`, `PIN_IMU_SCL` 두 값만 바꾸면 됩니다.
  이 BSP는 **아두이노 핀 번호 = nRF GPIO 번호**입니다 (P0.xx → `xx`, P1.xx → `32 + xx`).
- 대부분의 IMU 브레이크아웃 모듈에는 풀업 저항이 달려 있습니다. 칩만 쓰는 경우 SDA/SCL에 4.7kΩ 풀업을 3V3에 달아 주세요.

### I2C 주소 주의 — 0x6A

- **2026-09-30** (IMU 연결 전): 스캔하면 **0x6A에 IMU가 아닌 장치가 하나** 있었습니다
  (레지스터가 0x00~0x0C 13개뿐이고 가속도 레지스터가 없음. 보드의 전원/충전 IC로 보였지만 확인하지 못했습니다).
- **2026-10-07** (누코드로 가상 IMU 연결 후): 스캔 결과는 **0x6A 하나**이고, 그 주소가 `WHO_AM_I(0x0F) = 0x6A`
  (LSM6DS3TR-C / LSM6DSL 호환)로 응답합니다. 가속도·자이로 모두 정상 값이 나옵니다
  (가만히 두면 |a| ≈ 0.98g, 자이로 오차는 축마다 몇 °/s, 노이즈는 1°/s 미만).
  펌웨어는 이 장치를 `LSM6DS 계열 @ 0x6A`로 자동 감지합니다.

실물 IMU 모듈을 따로 붙인다면, 9/30에 본 0x6A 장치와 겹치지 않게 아래 주소를 권장합니다.

| IMU 계열 | 권장 주소 | 설정 |
|---|---|---|
| MPU-6050 / MPU-6500 | 0x68 | AD0 → GND |
| LSM6DS3 / LSM6DSL / LSM6DSO | **0x6B** | SA0 → 3V3 (**0x6A는 쓰지 말 것**) |

### 지원 IMU

펌웨어는 부팅 시 WHO_AM_I 레지스터를 읽어 아래 두 계열을 자동 감지합니다. 외부 라이브러리는 필요 없습니다.

- MPU-6050 / 6500 / 9250 계열 (0x68, 0x69)
- ST LSM6DS3 / LSM6DS3TR-C / LSM6DSL / LSM6DSO 계열 (0x6A, 0x6B)

다른 IMU(BMI160, ICM-42688 등)를 쓰려면 `imuBegin()`과 `imuRead()`에 드라이버를 추가하면 됩니다.
두 함수가 IMU 모델별 코드를 두는 유일한 곳입니다. `imuRead()`는 가속도를 **g**, 자이로를 **°/s** 단위로 돌려주면 되고, 나머지 코드는 고칠 필요가 없습니다.
2단계 방향 추정에는 자이로가 필요합니다 (두 계열 모두 ±16g, ±2000°/s로 설정).

감지에 실패하면 LED1이 빠르게 깜빡이고, 시리얼에 I2C 스캔 결과와 각 주소의 WHO_AM_I 값을 2초마다 출력합니다.

```
[I2C] scan: 0x68 0x6A
[IMU] 0x68 reg0x0F=.. reg0x75=68 reg0x00=..
```

### 버튼 드럼 모드 (IMU 없이)

부팅 시 IMU를 3번 찾아보고 없으면 **버튼 전용 모드**로 넘어가 BLE 광고를 시작합니다. IMU가 있어도 버튼은 항상 동작합니다.

| 보드 버튼 | 핀 | 드럼 (class) | 웹 키보드 |
|---|---|---|---|
| 1 | P0.11 | 스네어 (0) | `1` |
| 2 | P0.12 | 킥 (1) | `2` |
| 3 | P0.24 | 하이햇 (2) | `3` |
| 4 | P0.25 | 탐 (3) | `4` |

- 눌리는 순간에만 전송, 디바운스 25ms, 세기는 100 고정 (`BUTTON_VELOCITY`)
- 끄려면 `ENABLE_BUTTONS`를 0으로 (그러면 예전처럼 IMU를 찾을 때까지 기다림)
- 웹 화면의 패드 4개도 클릭/터치/키보드 `1`~`4`로 칠 수 있습니다 (보드 없이 시연용)

## 2. 아두이노 IDE 설정과 업로드

1. **파일 → 기본 설정 → 추가 보드 관리자 URL**에 아래 주소를 추가합니다 (이 PC에는 이미 추가되어 있습니다).
   ```
   https://raw.githubusercontent.com/Nucode01/Adafruit_nRF52_Arduino/refs/heads/master/package_nuduino_index.json
   ```
2. **보드 관리자**에서 `NUBoards nRF52 by NUCODE`를 설치합니다 (이 PC에는 1.0.2가 설치되어 있습니다).
3. **도구 → 보드 → NUBoards nRF52 → NU40DK nRF52840**를 선택합니다 (FQBN `nucode:nrf52:nu40dk`).
4. **도구 → 포트**에서 보드의 COM 포트를 선택합니다.
   - 앱 펌웨어가 돌 때와 부트로더 모드일 때 COM 번호가 다를 수 있습니다 (이 PC에서는 COM3/COM4). 업로드 도구가 자동으로 처리합니다.
5. `firmware/air_band_right/air_band_right.ino`를 열고 **업로드**합니다.
   Bluefruit, Wire 라이브러리는 BSP에 포함되어 있어 따로 설치할 게 없습니다.
6. **시리얼 모니터 115200 baud**를 엽니다. 정상이면 다음처럼 출력됩니다.
   ```
   === AirBand-R 2단계 (방향으로 드럼 고르기) ===
   [I2C] scan: 0x6A
   [IMU] LSM6DS 계열 @ 0x6A
   [IMU] 자이로 보정 중 — 1초 동안 가만히 두세요
   [IMU] 자이로 보정 완료 bias=(2.52,-4.04,-0.75)°/s
   [ZONE] 지금 방향을 정면(스네어)으로 잡음. 다시 잡으려면 'c'
   [BTN] 버튼 1~4 → 드럼 0~3 (스네어/킥/하이햇/탐)
   [BLE] 광고 시작: AirBand-R
   [CMD] c=정면 맞추기  m/x=모션 스트림 켜기/끄기  ?=상태
   HIT t=12345 peak=5.21g vel=36 cls=2 하이햇 heading=38.2 elev=-4.1
   ```
   위 로그는 2026-10-07 이 PC의 보드(가상 IMU 연결)에서 받은 것이고, 마지막 `HIT` 줄은 형식 예시입니다.
   **부팅 후 1초 동안은 센서를 가만히 두세요** (자이로 오차를 잽니다).

명령줄로 하려면 (IDE에 들어 있는 arduino-cli 사용):

```powershell
$cli = "$env:LOCALAPPDATA\Programs\Arduino IDE\resources\app\lib\backend\resources\arduino-cli.exe"
& $cli compile --fqbn nucode:nrf52:nu40dk -u -p COM3 firmware\air_band_right
```

### 펌웨어 디버그 플래그

| 플래그 | 기본 | 설명 |
|---|---|---|
| `DEBUG_HITS` | 1 | 타격마다 `HIT t=.. peak=..g vel=.. cls=.. 드럼 heading=.. elev=..`, 버튼마다 `BTN t=.. button=.. cls=..` 출력 |
| `DEBUG_ZONE` | 1 | 스틱 구역이 바뀌고 0.15초 유지되면 `[ZONE] 하이햇  heading=.. elev=..` 출력 |
| `DEBUG_RAW` | 0 | 1이면 100Hz로 `ax,ay,az,gx,gy,gz`(g, °/s) CSV만 출력. 다른 로그는 모두 꺼짐 (Edge Impulse 수집용) |

### 시리얼 명령

시리얼 모니터 입력창에 한 글자를 보내면 됩니다. 웹앱도 같은 글자를 BLE로 보냅니다.

| 글자 | 동작 |
|---|---|
| `c` | 정면 맞추기 — 지금 스틱 방향을 스네어(0°)로 |
| `a` | 축 맞추기 — 스틱 끝을 천장으로 세운 채 보내면 스틱 축을 재서 플래시에 저장 |
| `m` / `x` | 모션 스트림(방향 25Hz) 켜기 / 끄기 — 보통은 웹이 알아서 보냄 |
| `k` / `d` | 지휘 모드(타격 대신 박을 보냄) / 드럼 모드(기본). 연결이 끊기면 드럼으로 돌아감 — 지휘 화면이 알아서 보냄 |
| `?` | 상태 한 줄: IMU, BLE, 방향, 구역, 가속도, 부팅 보정 결과(`cal=ok(2.5°/s)`), 자이로 오차 |

### LED

- LED1: IMU를 못 찾으면 빠르게 깜빡임. 타격 표시는 기본 꺼짐 (디버그용 `HIT_LED 1`이면 타격마다 30ms 켜짐)
- LED2: BLE 연결 상태 (Bluefruit 기본 동작)

## 3. 웹앱 실행

Node.js 18 이상이 필요합니다 (이 PC의 WSL에는 nvm으로 v24가 설치되어 있습니다).
WSL에서 `/mnt/c` 아래 프로젝트로 `npm install`이 `EPERM: chmod`로 실패하면 `/etc/wsl.conf`에 아래를 넣고 `wsl --shutdown` 후 다시 여세요.

```ini
[automount]
options = "metadata,uid=1000,gid=1000,umask=022"
```

```bash
cd air-band/web
npm install
npm run dev        # http://localhost:5173
```

1. PC의 **Chrome 또는 Edge**로 `http://localhost:5173`을 엽니다.
2. 드럼 패드(또는 키보드 `1`~`5`, 스페이스바 = 무작위 테스트 타격)로 먼저 소리와 이펙트를 확인합니다.
3. **센서 연결** → 목록에서 `AirBand-R` 선택 → 보드 버튼 누르기 / 휘두르기.
4. **스틱 방향** 패널에 스틱이 가리키는 곳이 점으로 움직입니다. 스틱을 스네어 자리에 두고 **정면 맞추기**(키 `C`)를 누른 뒤,
   왼쪽 · 오른쪽 · 위로 겨누고 치면 하이햇 · 탐 · 크래시가 납니다. 오른쪽 막대는 가속도 크기이고, 주황 선이 타격 기준(2.5g)입니다.
   연결했는데 "방향 데이터 없음"이 뜨면 IMU가 없는 버튼 전용 모드이거나 1단계 펌웨어입니다.

정적 빌드: `npm run build` → `web/dist/`를 아무 HTTPS 정적 호스팅(GitHub Pages, Netlify 등)에 올리면 됩니다.

### 연주 녹음 · 재생 · MIDI · 공유 링크

자유 연주 화면의 **연주 녹음** 패널에서 씁니다. 보드 · 화면 패드 · 키보드로 친 타격이 모두 녹음됩니다.

- **● 녹음**(키 `R`) → 치기 → **■ 녹음 끝내기**. 목록에 길이와 타격 수가 나옵니다.
- **▶ 재생**: 소리는 오디오 시계에 미리 예약해서 녹음한 간격 그대로 납니다. 재생하면서 다시 녹음하면 겹쳐 치기가 됩니다 (재생되는 소리는 녹음되지 않음).
- **MIDI**: 표준 MIDI 파일(.mid)로 받습니다. General MIDI 드럼 채널(10번)이라 GarageBand · MuseScore · DAW에서 드럼으로 열립니다
  (스네어 38 · 킥 36 · 하이햇 42 · 탐 45 · 크래시 49, 120 BPM 기준 시간 그대로).
- **링크**: 연주를 주소 뒤(`#take=…`)에 담은 공유 링크를 복사합니다. 300타 연주가 약 1.6KB입니다. 서버에 아무것도 올리지 않으며,
  받은 사람은 링크를 열고 ▶만 누르면 됩니다. 보드도 블루투스도 필요 없어서 iPhone에서도 재생됩니다.
- 저장 위치: **이 브라우저에만** 저장됩니다 (localStorage, 최근 30개). 다른 기기로 옮기려면 링크를 쓰세요. 시크릿 창에서는 새로고침하면 사라집니다.
- 보드 타격의 녹음 시각은 BLE 수신 시각이 아니라 **보드 시각**으로 계산합니다. 무선 전송이 들쭉날쭉해도 녹음에는 흔들림이 들어가지 않습니다
  (시험: 보드 시각 250ms 간격, 수신 지연 20~80ms 무작위 → 녹음 간격 모두 250ms).

| 파일 | 역할 |
|---|---|
| `web/src/recorder.ts` | 녹음 · 공유 링크 인코딩 · MIDI 만들기 · 저장 (화면과 무관한 계산) |
| `web/src/main.ts` | 녹음 버튼 · 목록 · 재생 예약 |

### 리듬 게임 (`http://localhost:5173/rhythm.html`)

위 메뉴 **🥁 드럼 → 🎮 리듬 게임**.
- **⭐ 인기곡**(We Will Rock You 등 8곡): 공식 유튜브 뮤직비디오를 틀고 칩니다. 처음 한 번 ▶ 노래 틀기 → 노래의 "짝"마다 스페이스(또는 스틱) 8번 → 영상을 멈추지 않고 바로 게임. 박자는 브라우저에 저장돼 다음부터는 처음부터 바로 시작.
- **🔗 유튜브 링크로**: 아무 유튜브 링크를 붙여 넣으면 같은 방법(박마다 8번 탭)으로 칩니다. 유튜브 소리는 분석할 수 없어서 노트는 박자에 맞춘 난이도별 기본 패턴입니다. 치는 박자가 한쪽으로 계속 밀리면 남은 노트를 조금씩 옮겨 따라갑니다.
- **🎯 연습곡**: 음악 없이 메트로놈으로 치는 내장 곡.

- 4줄(스네어 · 킥 · 하이햇 · 탐)에 떨어지는 음표가 판정선에 닿을 때 치면 됩니다.
- 입력: 보드 버튼 1~4, 키보드 `1 2 3 4` 또는 `D F J K`, 화면 줄 터치. `Enter` 시작, `Esc` 그만두기
- 판정: Perfect ±45ms · Great ±90ms · Good ±140ms, 그 밖에 지나가면 Miss. 결과에 등급(S~D), 최고 기록 저장
- 연습곡 · 인기곡 목록은 `web/src/rhythm/charts.ts`(인기곡은 유튜브 영상 id · 대략 BPM · 탭 안내).
- 옵션: 가이드 소리, 메트로놈, 음표 속도, **입력 보정**(결과 화면에서 평균 타이밍을 보고 추천값을 한 번에 적용)
- 페이지가 다르므로 **보드는 리듬 게임 화면에서 다시 연결**해야 합니다.
- 2단계 스틱으로 칠 때: 정면 = 스네어 줄, 왼쪽 = 하이햇 줄, 오른쪽 = 탐 줄입니다. 킥 줄은 보드 버튼 2로 칩니다. 크래시(class 4)는 4줄에 없어서 무시됩니다.

| 파일 | 역할 |
|---|---|
| `web/rhythm.html` | 게임 화면 |
| `web/src/rhythm/main.ts` | 진행 · 입력 · 그리기 · 소리 예약 |
| `web/src/rhythm/game.ts` | 판정 · 점수 · 콤보 · 등급 (순수 계산) |
| `web/src/rhythm/charts.ts` | 곡(악보) 데이터 |

### HTTPS / 브라우저 지원

- Web Bluetooth는 **HTTPS 또는 localhost에서만** 동작합니다. `http://192.168.x.x:5173` 같은 주소로는 연결 버튼이 비활성화됩니다.
- 지원: PC Chrome/Edge (Windows, macOS, Linux*), Android Chrome.
- 미지원: **iOS Safari/Chrome**, Firefox. 이 경우 화면 상단에 안내 메시지가 뜹니다. (iOS는 Bluefy 같은 Web Bluetooth 지원 앱 브라우저로 시도해 볼 수 있습니다.)
  \* Linux는 `chrome://flags/#enable-experimental-web-platform-features` 설정이 필요할 수 있습니다.

### 폰(Android)에서 테스트

- **방법 A (권장)**: USB 디버깅을 켜고 `adb reverse tcp:5173 tcp:5173` → 폰 Chrome에서 `http://localhost:5173`을 엽니다 (localhost라서 HTTPS가 필요 없습니다).
- **방법 B**: `npm run build` 결과를 HTTPS 호스팅에 올리고 접속합니다.

### 샘플 파일

`web/public/samples/{snare,kick,hihat,tom}.wav`가 있으면 그 파일을 쓰고, 없으면 해당 드럼 소리를 합성해서 씁니다. 화면 상단의 "소리" 항목에서 어느 쪽을 쓰는지 표시됩니다.
어느 쪽이든 앱 시작 시 한 번만 AudioBuffer로 준비하고, 타격 때는 재생만 합니다.

### 화면의 지연 표시

| 항목 | 의미 |
|---|---|
| 수신 → 재생 호출 | BLE notify를 받은 시각부터 `start()`를 부른 시각까지. 보통 1ms 미만이어야 합니다 |
| 오디오 출력 버퍼 | `AudioContext.baseLatency + outputLatency`. OS/오디오 장치에 따라 다릅니다 (블루투스 이어폰은 100ms 이상) |
| BLE 지터 | (수신 시각 − 보드 타임스탬프)가 세션 최솟값보다 얼마나 늦었는지. 크게 흔들리면 연결 간격이나 무선 환경 문제입니다 |

보드 시계와 브라우저 시계는 맞춰져 있지 않으므로, 센서→브라우저 절대 지연은 표시하지 않고 **지터(상대값)** 만 표시합니다.

## 4. 튜닝 가이드

모든 상수는 `air_band_right.ino` 상단 "타격 감지 / 세기 튜닝 상수"에 있습니다. 값은 **중력 1g가 포함된 3축 가속도 크기(g)** 입니다.

| 증상 | 조정 |
|---|---|
| 타격이 안 잡힘 / 약하게 치면 안 잡힘 | `HIT_THRESHOLD_G` ↓ (예: 2.5 → 2.0) |
| 걷거나 손만 움직여도 소리가 남 | `HIT_THRESHOLD_G` ↑ (예: 2.5 → 3.0~3.5) |
| 한 번 쳤는데 두 번 소리가 남 (스틱 반동) | `REFRACTORY_MS` ↑ (예: 60 → 90) |
| 빠른 연타 중 일부가 빠짐 | `REFRACTORY_MS` ↓ (예: 60 → 40). 단, 이중 타격과 균형 필요 |
| 세게 쳐도 소리가 작음 | `VEL_MAX_G` ↓ (예: 12 → 8) |
| 약하게 쳐도 소리가 큼 / 세기 차이가 없음 | `VEL_MAX_G` ↑, 또는 웹의 `velocityToGain()` 곡선 지수(1.6)를 ↑ |

튜닝 요령: `DEBUG_HITS=1` 상태에서 시리얼 모니터를 켜고, 약하게/세게/걷기/가만히 들기를 각각 해 보면서 `peak=` 값을 봅니다.
걷기에서 나오는 최대 peak보다 조금 높게 `HIT_THRESHOLD_G`를, 가장 세게 쳤을 때 peak 근처로 `VEL_MAX_G`를 잡으면 됩니다.

동작 원리:
- 샘플링은 `micros()` 경과시간 비교로 10ms(100Hz) 주기를 유지합니다.
- 직전 샘플이 **국소 최대값**(앞 샘플보다 크고 뒤 샘플보다 작지 않음)이고, 임계값 이상이며, 불응기가 지났을 때 타격으로 판정합니다. 피크 값을 정확히 쓰려고 한 샘플(10ms) 뒤에 판정합니다.
- 판정 결과는 FreeRTOS 큐에 대기 없이(`timeout 0`) 넣고, 별도 태스크가 BLE notify를 보냅니다.
  Bluefruit의 notify는 송신 버퍼가 가득 차면 최대 100ms까지 대기할 수 있어서, 샘플링 루프와 분리해 두었습니다.
- IMU 측정 범위는 ±16g입니다. 매우 세게 휘두르면 16g에서 잘릴 수 있습니다.

## 5. 2단계: 방향으로 드럼 고르기

```
             ┌───────── 크래시 (기준보다 25° 이상 위) ─────────┐
   하이햇     │            스네어            │      탐
 (왼쪽 25°↑)  │          (정면 ±25°)          │ (오른쪽 25°↑)
             └──────────────────────────────┘
                킥 = 보드 버튼 2 (발이라 스틱 구역에 없음)
```

**사용법**
1. 부팅 후 1초 동안 센서를 가만히 둡니다 (자이로 오차 측정). 이때 자세가 첫 기준(정면)이 됩니다.
2. 스틱을 스네어 칠 자리에 두고 **정면 맞추기**(웹 버튼 · 키 `C` · 시리얼 `c`)를 누릅니다.
3. 왼쪽으로 돌려서 치면 하이햇, 오른쪽은 탐, 위로 들고 치면 크래시입니다. 판정은 **가속도 피크 순간의 방향**으로 합니다.
4. 시간이 지나 구역이 어긋나 보이면 정면 맞추기를 다시 누릅니다.

**동작 원리** (`orientation.h`)
- 자이로(회전 속도)를 적분해 방향을 구하고, 가만히 있을 때 보이는 중력으로 위아래 기울기를 계속 바로잡습니다 (Mahony 상보 필터).
  휘두르는 중이나 타격 충격처럼 |가속도|가 1g에서 0.25g 넘게 벗어나면 중력 보정을 쉽니다.
- 좌우 방향은 중력으로 바로잡을 수 없어서 자이로 오차가 쌓이면 조금씩 흘러갑니다. 부팅 때 1초 평균으로 오차를 재고,
  그 뒤에도 0.5초 이상 가만히 있으면 오차를 천천히 다시 맞춥니다.
- 측정값 (2026-10-07, 이 PC의 보드 + 가상 IMU, 가만히 둔 상태): 좌우 방향이 **1분에 약 0.3°** 흘렀습니다.
  실제로 휘두를 때의 드리프트는 아직 재지 못했습니다 (아래 "확인 필요").
- PC 시험: 참 자세를 시뮬레이션해 만든 자이로·가속도(오차·노이즈·8g 충격 포함)로 시험했습니다.
  60초 정지 드리프트, 좌/우 40° 돌리기, 35° 들기, 왼쪽·정면 각 20연타가 모두 기대한 구역으로 나왔습니다.

**구역 튜닝** (`air_band_right.ino` 상단 "드럼 구역")

| 증상 | 조정 |
|---|---|
| 좌우가 반대로 나옴 / 위아래로 휘두르는데 좌우가 바뀜 | 스틱 축이 실제와 다름. **스틱 끝을 천장으로 세우고 가만히 든 채 "축 맞추기"(명령 `a`)** → 스틱을 스네어 쪽으로 겨누고 "정면 맞추기"(`c`). 축은 보드 플래시에 저장됨. 직접 고치려면 `STICK_AXIS` |
| 스네어를 치는데 하이햇/탐이 나옴 | `ZONE_LEFT_DEG` / `ZONE_RIGHT_DEG` ↑ (예: 25 → 35) |
| 내려칠 때 크래시가 나옴 | `ZONE_UP_DEG` ↑ |
| 1단계처럼 항상 스네어만 | `USE_ZONE_CLASSIFIER`를 0으로 |

웹의 방향 화면 경계선은 `web/src/motion.ts`의 `ZONE_DEG`로 그립니다. 펌웨어 값을 바꾸면 같이 바꾸세요 (판정 자체는 보드가 합니다).
`STICK_AXIS`는 스네어 자리에서 위아래로 휘둘러 보고, `[ZONE]` 로그나 웹 화면에서 점이 위아래로만 움직이면 맞게 설정된 것입니다.

**I2C 버스 풀기**: 센서가 데이터를 보내는 도중에 보드가 리셋되면 센서가 SDA를 붙잡아 부팅이 `[I2C] scan:`에서 멈출 수 있습니다
(업로드를 연달아 하다가 실제로 겪었습니다). 그래서 부팅할 때 버스가 막혀 있으면 SCL을 최대 9번 깜빡여 풀고
`[I2C] 버스가 막혀 있어 풀었습니다` 를 출력합니다.

## 6. 다음 단계: TinyML 분류 붙이기

2단계의 방향 구역은 규칙 기반입니다. 동작 자체(세게 내려치기 / 살짝 긁기 / 림샷 등)를 구분하려면 TinyML을 붙입니다.

1. **데이터 수집**
   - `DEBUG_RAW`를 1로 바꾸고 업로드합니다. 시리얼로 `ax,ay,az,gx,gy,gz`가 100Hz로 나옵니다.
   - 시리얼 모니터는 닫고 `npm install -g edge-impulse-cli` → `edge-impulse-data-forwarder`를 실행한 뒤, 프로젝트와 축 이름(`ax,ay,az,gx,gy,gz`)을 지정합니다.
   - Edge Impulse Studio에서 클래스별(스네어, 하이햇, 심벌, 탐 …)로 동작을 녹화합니다. 각 샘플은 타격 한 번이 **0.2초 창**(20샘플) 안에 들어오도록 자릅니다. 펌웨어의 링버퍼 길이와 같아야 합니다.
2. **학습**
   - Impulse: 시계열 입력(창 200ms, 100Hz) → Spectral Analysis 또는 Raw Data → Classification.
   - 배포: **Arduino library**로 내보낸 뒤, 아두이노 IDE에서 **스케치 → 라이브러리 포함 → .ZIP 라이브러리 추가**.
3. **`classifyHit` 교체**
   - `classifyHit(const SampleBuffer& buf, uint8_t peakZone)` 안에서 `buf.at(0)` ~ `buf.at(buf.count - 1)`(오래된 순)의 `acc`, `gyro`를 `ax, ay, az, gx, gy, gz` 순서로 펼쳐 Edge Impulse의 `run_classifier()` 입력으로 넣습니다.
   - 결과를 그대로 반환하거나, `peakZone`(방향 구역)과 조합합니다. 예) 모델은 "치기 / 긁기", 구역은 드럼 종류.
   - 추론 시간이 수 ms를 넘으면 샘플링이 밀리므로, 그 경우 추론을 별도 태스크로 옮기고 결과를 큐로 받도록 바꾸세요.
   - 웹의 `web/src/audio.ts`에 있는 `DRUM_CLASSES`에 클래스 번호 → 샘플 이름을 추가하고 `public/samples/`에 wav 파일을 넣습니다.

## BLE 스펙 요약

- Nordic UART Service: `6e400001-b5a3-f393-e0a9-e50e24dcca9e`
  - TX(notify, 보드→브라우저) `6e400003-…`, RX(write, 브라우저→보드) `6e400002-…` (한 글자 명령: `c` `m` `x`, 위 "시리얼 명령" 참고)
- 광고 이름 `AirBand-R` (광고 패킷에 NUS UUID, 스캔 응답에 이름)
- 연결 간격 7.5~15ms 요청 (중앙 장치가 다른 값을 줄 수 있음)
- 타격 패킷 8바이트, little-endian

| 바이트 | 필드 | 값 |
|---|---|---|
| 0 | hand | 0 = 오른손 |
| 1 | mode | 0 = 드럼 · 1 = 지휘 |
| 2 | class | 드럼: 0 스네어 · 1 킥 · 2 하이햇 · 3 탐 · 4 크래시 / 지휘: 0 = 박 |
| 3 | velocity | 드럼: 1~127 (타격이면 최소 1) / 지휘: 박 크기(도) × 2 |
| 4-7 | timestamp | 보드 `millis()` (uint32). 지휘는 박 바닥점 시각 |

축 맞추기 결과 패킷: `[0] 0x81 · [1] 1=성공 0=실패 · [2..7] 축 x,y,z × 10000 (int16)`

**모션 패킷 (8바이트, little-endian)** — `m` 명령 후 25Hz. 웹은 8바이트씩 잘라 0번 바이트로 타격/모션을 구분합니다.

| 바이트 | 필드 | 값 |
|---|---|---|
| 0 | type | `0x80` (타격 패킷의 hand는 0/1이라 겹치지 않음) |
| 1 | zone | 지금 치면 나올 드럼 클래스 |
| 2-3 | heading | 기준 대비 좌우 각도 × 10 (int16, + = 왼쪽) |
| 4-5 | elevation | 기준 대비 위아래 각도 × 10 (int16, + = 위) |
| 6-7 | accel | 직전 40ms 최대 가속도 크기, mg (uint16) — TinyML 입력과 같은 값 |

타격은 모션보다 먼저 나갑니다: 전송 태스크가 타격 큐를 먼저 보고, 모션은 1칸 큐에 최신 값만 덮어씁니다.
