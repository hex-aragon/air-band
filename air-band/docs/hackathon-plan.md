## 2. 원칙 · 설계

### 2.1 블록체인은 "선택"

| | 일반 사용자 (지갑 없음) | 블록체인 사용자 (지갑 연결) |
|---|---|---|
| 자유 연주 · 드럼 키트 · 리듬 게임 · TinyML | ✅ 전부 그대로 | ✅ 전부 그대로 |
| 점수 · 최고 기록 | 브라우저에 저장 | 브라우저 + 온체인 리더보드 |
| 보드 서명 (Proof of Play) | 받아서 **브라우저에 보관** | 트랜잭션으로 제출 |
| 보상 ($BEAT) | — | 받기 (하루 상한) |
| AI 코치 | 무료 기본 피드백 (지금 결과 화면의 타이밍 분석 확장) | 유료 심화 레슨 (x402) |

- 지갑 버튼은 결과 화면과 헤더 구석에만. 첫 화면 · 게임 흐름에는 지갑 이야기 없음
- **나중에 연결해도 손해 없음:** 서명된 기록을 브라우저에 쌓아 두고, 지갑 연결 시 이번 시즌 기록 일괄 제출
- 블록체인 코드는 `web/src/chain/`에 분리, **지갑 연결 시에만 동적 import** → 일반 사용자는 솔라나 라이브러리를 내려받지 않음
- **devnet 전용.** 토큰 판매 · 상장 · 수익 약속 금지 (국내 법 이슈). 발표에서는 "게임 보상 포인트"로 설명

### 2.2 전체 구조

```
[NU40 스틱 (오른손)] ── BLE (NUS) ──▶ [웹 (gh-pages)]
                                       게임 → 결과 요약 → 보드에 서명 요청 → 서명된 결과를 브라우저에 보관
                                       │ (지갑 연결한 사람만)
                                       ├──▶ [솔라나 프로그램 (Anchor, devnet)]
                                       │      register_device · submit_score(Ed25519 검증) · claim_reward
                                       │      PDA: Device · Season · Leaderboard · Player
                                       └──▶ [AI 코치 API (x402)]  402 → 지갑 결제 → 레슨 (Claude)
```

### 2.3 Proof of Play 흐름

1. 곡이 끝나면 웹이 결과 요약 생성: `곡 id · 점수 · 판정 개수 · 타격 기록 해시 · 보드 시각 범위 · 지갑 주소(있으면) · 시즌 nonce`
2. 웹 → 보드: 요약 해시를 BLE 명령으로 전송 (새 명령 `s` + 32바이트)
3. 보드: 게임 중 자기가 보낸 타격 패킷 누적 해시와 대조 → 맞으면 **보드 개인키(Ed25519)로 서명** 반환
4. 지갑 사용자는 `[Ed25519 검증 명령, submit_score]`를 한 트랜잭션으로 전송. 프로그램은 instructions sysvar로 "등록된 보드 공개키가 이 요약에 서명했는지" 확인
5. 키보드 · 터치 기록은 서명이 없으므로 로컬 기록만 (온체인 X)
- 펌웨어 빌드에 이미 `Adafruit_nRFCrypto`가 링크됨. 서명 구현은 먼저 Monocypher(소프트웨어 Ed25519)로

### 2.4 토큰 흐름 ($BEAT, devnet)

| 들어오는 곳 | 나가는 곳 |
|---|---|
| 인증된 플레이 보상 (하루 상한) | 곡 · 악보 팩 → 수익이 악보 제작자에게 |
| 시즌 순위 상금 | 토너먼트 참가비 → 상금 풀 |
| 내 악보가 플레이될 때 로열티 | AI 코치 심화 레슨 (USDC 또는 $BEAT) |

- 보상은 시즌 풀 안에서만, 기기당 · 지갑당 하루 상한. 해커톤 범위는 "인증 보상 + 리더보드 + 코치 결제"까지

### 2.5 에이전트 결제 아이디어
- **AI 코치:** 연주 기록(빠름/늦음 ms, 방향 오판, 드럼별 정확도) → 레슨 · 연습 곡. 1회당 x402 소액 결제
- **에이전트 간 결제 (로드맵):** 코치 에이전트가 맞춤 악보를 "악보 제작자 에이전트"에게서 x402로 구매 → 대금이 제작자 지갑으로

### 펌웨어 (`firmware/air_band_right/`)
- 2단계: IMU(LSM6DS @0x6A 가상 IMU · MPU6050 자동 감지) → Mahony 방향 추정(`orientation.h`) → 구역(정면 스네어 · 왼쪽 하이햇 · 오른쪽 탐 · 위 크래시, ±25°) → 피크 타격 감지 → BLE NUS 8바이트 패킷. 모션 패킷 0x80 25Hz. 명령 `c` 정면 · `m`/`x` 모션 · `?` 상태
- **TinyML 연동:** `USE_TINYML 1` + `zone_model.h`가 폴더에 있으면(`__has_include`) `classifyHit()`이 모델 사용, 없으면 규칙. `?` 상태에 `classifier=tinyml|rule`. 둘 다 컴파일 확인, 모델 +2.7KB 플래시. 25Hz 방향 기록 6개 링버퍼
- `DEBUG_RAW 1` → Edge Impulse data forwarder용 CSV(ax,ay,az,gx,gy,gz 100Hz)

## 5. 하드웨어 메모

### 보드
- NUCODE NU40 DK: nRF52840, BLE 5.4, UF2 부트로더(리셋 두 번 → `BARAM-NU40` 드라이브). 버튼 4개(P0.11 · P0.12 · P0.24 · P0.25), I2C P0.26/P0.27. 실제 크기(mm)는 공개 자료에서 못 찾음 → 직접 재야 함
- 두 번째 보드 선택:

| 선택지 | 작업량 | 판단 |
|---|---|---|
| NU40 DK 1대 더 | 펌웨어 기기 이름 · hand 값만 변경 | ✅ 일정 짧으면 이것 |
| nRF54L15 DK를 킥(발)으로 | Arduino BSP 미지원 → Zephyr(nRF Connect SDK)로 타격 감지 + BLE만 새로 작성 | 54DK 꼭 쓰면 이것 |
| nRF54L15 DK를 왼손 스틱으로 | Zephyr 포팅 + 방향 계산 + 117×64mm 손목 장착 | ❌ 해커톤 범위 밖 |

- 패킷에 이미 hand 바이트(0 오른손 / 1 왼손) 있음. 웹은 지금 보드 1대만 연결

### 운영체제 (사용자가 "zapier"라고 부른 것 = Zephyr)
- NU40은 Zephyr 공식 보드: `nucode_nu40/nrf52840`, `west build -b nucode_nu40/nrf52840 samples/hello_world`, `zephyr.uf2`를 드래그
- **현재 펌웨어는 Zephyr가 아님:** Arduino BSP(NUBoards nRF52 by NUCODE, FQBN `nucode:nrf52:nu40dk`) 위의 FreeRTOS. 해커톤에는 옮기지 않음 (Thread/Matter · 제품화 때 검토)

### 스틱 고정 (사용자 안내 완료)
- 기본: 드럼스틱(5A) 손잡이 끝에 납작한 판(아크릴 · 합판) → 폼 양면테이프 2~3겹 + **케이블타이 2~3개 필수**(테이프만으로는 밀림) → 보드는 판 위에 테이프 + 케이블타이, IMU는 **+X 화살표가 스틱 끝** 방향, 전선은 절연테이프 · 글루건 고정, 손목 스트랩
- 보드가 크면: 보드 + 미니 보조배터리는 러닝 암밴드, 스틱엔 IMU만 (수축튜브), 실리콘 전선 26AWG 꼬아서 연결
- 확인: 세게 털어도 흔들림 없음 → 켤 때 1초 정지(자이로 보정) → 드럼 키트 화면에서 C 후 왼쪽으로 돌리면 하이햇이어야 함 (반대면 STICK_AXIS 수정)
- 사용자는 연결선은 이미 있음. 다이소: 판 · 폼테이프 · 케이블타이 · 절연테이프 · 글루건. 쿠팡: 5A 드럼스틱 · 3M VHB · 수축튜브 · GY-521(MPU6050, 0x68) 등
