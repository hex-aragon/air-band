02무엇으로 만들었나

🟦

NU40 DK 보드

누코드의 개발용 보드. 안에 nRF52840이라는 칩이 있어 블루투스와 프로그램 실행을 둘 다 합니다. 버튼 4개, LED 4개가 달려 있습니다.

🧭

IMU (모션 센서)

움직임을 재는 작은 부품. 스마트폰이 가로·세로를 아는 것도 이 센서 덕분입니다. 아직 연결 안 됨 → 이번엔 버튼으로 대신했습니다.

🌐

웹 브라우저

PC의 크롬·엣지, 안드로이드 크롬. Web Bluetooth(웹페이지가 블루투스를 쓰는 기능)와 Web Audio(웹페이지가 소리를 내는 기능)를 씁니다.

준비물은 세 가지입니다. 블루투스가 되는 보드, 움직임을 재는 센서, 그리고 크롬 같은 웹 브라우저. 센서는 아직 도착하지 않아서, 이번에는 보드에 있는 버튼 4개로 대신했습니다.

03전체 구조

입력은 버튼이든 센서든 보드 안에서 똑같은 "쪽지"로 바뀌어 같은 길로 나갑니다. 그래서 나중에 센서를 붙여도 웹은 고칠 필요가 없습니다.

왼쪽이 입력, 가운데가 보드, 오른쪽이 브라우저입니다. 점선으로 된 센서는 아직 연결되지 않았습니다. 버튼이든 센서든 보드가 같은 형식의 쪽지로 바꿔서 보내기 때문에, 브라우저 쪽은 입력이 뭔지 신경 쓰지 않습니다.

04블루투스로 어떻게 보내나

BLE
Bluetooth Low Energy. 전기를 아주 적게 쓰는 블루투스. 스마트워치·무선 이어폰에서 쓰는 방식
광고
보드가 주변에 "나 여기 있어요! 이름은 AirBand-R"이라고 계속 외치는 것. 그래서 브라우저 목록에 이름이 뜸
연결
브라우저가 목록에서 골라 1:1로 짝을 맺는 것
NUS
Nordic UART Service. 보드와 기기 사이에 문자 메시지 주고받는 통로를 여는 표준 방식
notify
보드가 새 소식이 생기면 먼저 밀어서 보내는 것 (휴대폰 푸시 알림처럼)
연결 간격
둘이 몇 ms마다 소식을 주고받나. 7.5~15ms로 요청 → 짧을수록 빨리 도착

📱 비유: 단톡방

① 보드가 "방 열었어요"라고 알림 (광고)
② 브라우저가 방에 들어감 (연결)
③ "새 메시지 알림 켜기" (notify 구독)
④ 버튼 누를 때마다 보드가 메시지 보냄

ms(밀리초) = 1/1000초. 15ms는 눈 깜빡이는 시간(약 100~150ms)보다 10배 빠름

블루투스 용어를 단톡방에 비유해 보겠습니다. 보드가 방을 열었다고 알리는 게 '광고'이고, 브라우저가 들어가는 게 '연결', 알림을 켜는 게 'notify 구독'입니다. 그 뒤로 버튼을 누를 때마다 보드가 메시지를 보냅니다. 메시지를 확인하는 주기가 '연결 간격'인데, 7.5에서 15ms로 아주 짧게 요청했습니다.

손모드드럼 종류세기시각 (4칸을 합쳐 큰 숫자 하나)
칸뜻값의 의미
0 손어느 손인가0 = 오른손 (나중에 왼손 보드는 1)
1 모드어떤 악기 모드인가0 = 드럼 (나중에 다른 악기 추가 가능)
2 드럼 종류무슨 드럼인가0 스네어 · 1 킥 · 2 하이햇 · 3 탐

4~7 시각언제 쳤나보드가 켜진 뒤 흐른 시간(ms). 위 예시는 112,389ms ≈ 1분 52초
보드가 보내는 쪽지는 8칸짜리입니다. 한 칸에는 0부터 255까지 숫자 하나만 들어갑니다. 이 한 칸을 '바이트'라고 부릅니다. 버튼 2를 누르면 오른손, 드럼, 킥, 세기 100이 들어가고, 나머지 4칸에는 언제 눌렀는지가 들어갑니다.

06쪽지 속 어려운 말 풀이

바이트(byte)
숫자 0~255 하나를 담는 칸. 8바이트 = 칸 8개. 문자 메시지 한 통보다 훨씬 작아서 빠르게 보냄
millis()
보드가 켜진 뒤 흐른 시간을 ms로 알려 주는 보드 속 스톱워치
시각이 4칸인 이유
112,389는 한 칸(최대 255)에 안 들어감 → 4칸에 나눠 담음. 4칸이면 약 49일까지 셀 수 있음
LE (little-endian)
나눠 담을 때 작은 자리부터 적는 규칙. 보드와 브라우저가 같은 규칙을 써야 숫자를 제대로 다시 합침
uint32
"음수 없는 32비트(=4바이트) 정수"라는 자료형 이름
MIDI velocity
전자 키보드·드럼이 "건반을 얼마나 세게 눌렀나"를 1~127로 표현하는 업계 표준

112,389를 4칸에 나누는 것은 숫자를 자리별로 나눠 적는 것과 같습니다. 다만 10진법이 아니라 256진법이라 [5, 183, 1, 0]이 됩니다. (5 + 183×256 + 1×65,536 = 112,389)

시각은 숫자가 커서 한 칸에 안 들어갑니다. 그래서 4칸에 나눠 담는데, 작은 자리부터 담는 규칙을 little-endian이라고 합니다. 보드와 브라우저가 같은 규칙을 써야 원래 숫자로 되돌릴 수 있습니다.

07센서로 "쳤다!"를 알아채는 법 (센서 연결 후 동작)

100Hz 샘플링
1초에 100번(10ms마다) 센서 값을 읽음. 1초에 100장 사진 찍기
g
중력 단위. 가만히 있어도 1g, 휘두르다 멈추면 수 g ~ 10g 이상
국소 최대값
그래프의 산꼭대기. 올라가다 내려가기 시작한 지점
임계값 2.5g
이걸 넘어야 타격으로 인정하는 문턱. 걷기·손 흔들기 무시용
불응기 60ms
한 번 친 직후 0.06초는 귀 막기. 스틱 튕김을 두 번 친 걸로 세지 않게
세기
꼭대기 높이로 결정: 2.5g → 1, 12g 이상 → 127
센서를 붙이면 이렇게 동작합니다. 1초에 100번 흔들림의 크기를 재서, 문턱 2.5g를 넘는 산꼭대기가 나오면 '쳤다'고 판단합니다. 꼭대기가 높을수록 세게 친 것이고, 친 직후의 작은 튕김은 무시합니다.

09그런데… 센서가 없었다

[I2C] scan: 0x6A
[IMU] 감지 실패 — 재시도
[IMU] 0x6A reg0x0F=FF reg0x75=FF

보드가 켜질 때 출력한 로그

보드가 부품들에게 출석을 불렀더니 0x6A 한 명만 대답했고, 그건 센서가 아니라 보드의 전원 관리 부품이었습니다. 센서를 기다리느라 보드가 블루투스도 켜지 않고 멈춰 있었습니다.

I2C
보드와 부품을 선 2개로 연결해 대화하는 방식
scan
연결된 부품의 출석 부르기
0x6A
부품의 번호(주소). 0x는 16진수라는 표시 (0x6A = 106)
WHO_AM_I
부품에게 "너 누구야?" 묻는 칸. 센서면 정해진 값으로 대답
FF
대답 없음 → 센서가 아님
SA0 → 3V3
센서 번호를 바꾸는 핀. 일부 센서는 기본 번호가 0x6A라 0x6B로 바꿔야 겹치지 않음
처음에 보드를 흔들어도 아무 반응이 없었습니다. 로그를 보니 보드에 연결된 부품이 전원 관리 칩 하나뿐이었습니다. 이 보드에는 모션 센서가 내장되어 있지 않아서 따로 연결해야 하는데, 아직 없었던 겁니다.

10그래서: 보드 버튼 4개로 먼저 쳐 보기

킥버튼 2 · 키보드 2
하이햇버튼 3 · 키보드 3

  • 센서를 3번 찾아보고 없으면 버튼 모드로 켜짐
  • 버튼은 누르는 순간에만 전송, 세기는 100 고정
  • 디바운스 25ms: 버튼이 눌리는 순간 접점이 떨려서 여러 번 눌린 것처럼 보이는 것을 무시

센서만 빼고 보드 → 블루투스 → 브라우저 → 소리 전체 길을 먼저 검증했습니다. 센서가 오면 입력만 바꿔 끼우면 됩니다.

센서를 기다리는 대신, 보드에 원래 달린 버튼 4개를 드럼 4개로 바꿨습니다. 이렇게 하면 센서 말고 나머지 전 구간이 제대로 동작하는지 먼저 확인할 수 있습니다.

11브라우저 화면

  • 센서 연결: 보드와 블루투스 짝 맺기
  • 패드 4개: 누른 드럼이 반짝 (마우스·키보드로도 칠 수 있음)
  • 물결: 드럼마다 위치·색이 다르고 세게 칠수록 크게 퍼짐
  • 숫자 3개: 소리가 얼마나 빨리 나는지
  • 기록: 언제 · 무슨 드럼 · 세기 · 입력(보드/화면)
브라우저 화면입니다. 센서 연결 버튼으로 보드와 연결하고, 보드 버튼을 누르면 해당 패드가 반짝이고 소리가 납니다. 보드가 없어도 마우스나 키보드 1~4로 칠 수 있어서 시연용으로도 씁니다.

12소리는 어떻게 내나

칠 때마다 소리를 새로 만들면 늦습니다. 그래서 페이지가 열릴 때 드럼 4개 소리를 미리 만들어 두고, 신호가 오면 재생 버튼만 누릅니다. 노래방 반주를 미리 받아 두는 것과 같습니다.

소리 파일이 없어도 코드로 드럼 소리를 합성합니다.

드럼만드는 법
스네어"둥" (낮은 음) + "치" (잡음)
킥아주 낮은 "쿵" — 음이 뚝 떨어짐
하이햇짧고 높은 "츳" 잡음
탐킥보다 높은 "둥"

세기 → 볼륨: 사람 귀는 작은 소리 차이에 민감해서 곡선으로 바꿈 (세기 100 → 볼륨 68%)

소리는 미리 만들어 두고 재생만 합니다. 그래서 신호를 받고 재생하기까지 0.1ms밖에 안 걸립니다. 드럼 소리 파일이 없어도 음정 있는 소리와 잡음을 섞어서 코드로 드럼 소리를 만듭니다.

블루투스 흔들림(지터)
평소보다 몇 ms 늦게 왔나. 보드 연결 시 표시

늦어지는 건 대부분 컴퓨터 스피커 쪽입니다. 블루투스 이어폰을 쓰면 여기에 0.1초 이상 더 늦어지니, 시연할 때는 유선 스피커가 좋습니다.

소리가 나기까지 걸리는 시간을 세 부분으로 나눠 보여 줍니다. 브라우저 처리는 0.1ms로 거의 0이고, 대부분은 윈도우가 소리를 스피커로 내보내는 58ms입니다. 블루투스 이어폰은 더 느리니 유선 스피커를 권합니다.

15만들면서 막혔던 곳

증상원인 (쉽게)해결
보드를 흔들어도 반응 없음모션 센서가 연결되어 있지 않았음버튼 모드 추가
개발 도구 설치 실패윈도우 폴더를 리눅스(WSL)에서 쓸 때 권한 정보가 없었음WSL 설정(wsl.conf) 수정 후 재시작
코드를 고쳐도 화면이 그대로윈도우 폴더 파일 변경을 개발 서버가 알아채지 못함주기적으로 직접 확인(폴링)하게 설정
물결이 타원으로 찌그러짐그림판 크기를 처음에 한 번만 잼크기 바뀔 때마다 다시 재게 수정
보드 버튼이 안 먹는 것 같음브라우저와 블루투스 연결 전에는 보드가 아무것도 안 보냄진단으로 버튼 정상 확인 + 화면에 "먼저 연결하세요" 안내
만들면서 막혔던 부분들입니다. 특히 마지막은, 보드 버튼 신호가 브라우저와 연결된 다음에만 전송된다는 점이라, 화면에 먼저 연결하라는 안내를 넣었습니다.

17직접 해 보기

🖱️ 보드 없이

① 크롬에서 hex-aragon.github.io/air-band 열기
② 화면 패드 클릭, 또는 키보드 1 · 2 · 3 · 4
🥁 리듬 게임: /air-band/rhythm.html

🟦 보드로

① 보드를 USB로 연결
② 센서 연결 → AirBand-R → 페어링
③ 상태가 "연결됨"으로 바뀌면
④ 보드 버튼 1~4 누르기

연결 전에는 보드 버튼을 눌러도 소리가 나지 않습니다 (보드가 보낼 곳이 없어서). 보드의 LED1만 깜빡입니다.

직접 해 보는 방법입니다. 보드 없이도 화면이나 키보드로 칠 수 있고, 보드로 치려면 먼저 센서 연결을 눌러 AirBand-R과 연결해야 합니다.
