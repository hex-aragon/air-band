# 에어 밴드 데모 개발 작업지시서 (Claude용 프롬프트)

아래 전체를 복사해서 Claude(또는 Claude Code)에 붙여 넣으세요.

---

## 역할

너는 임베디드 펌웨어와 웹 프론트엔드를 함께 다루는 시니어 엔지니어다. 아래 프로젝트의 1단계 데모를 처음부터 끝까지 동작하는 상태로 만들어라. 설명보다 실제로 돌아가는 코드가 우선이다.

## 프로젝트 개요

허공에서 드럼을 치면 소리가 나는 "에어 밴드" 장치를 만든다. 손에 쥔 센서가 타격 동작을 인식하고, 폰이나 PC 브라우저에서 드럼 소리와 리듬게임 화면이 나온다. 서버는 쓰지 않는다.

**최종 그림 (참고용, 이번 범위는 아님)**
- 양손 센서 → 드럼(스네어·하이햇·심벌·탐), 기타(스트럼 + 왼손 코드 구역), 베이스(뜯기)
- 여러 명이 각자 악기를 맡는 밴드 모드

## 하드웨어 전제

- 보드: NUCODE NU40 DK (Nordic nRF52840, Cortex-M4F 64MHz, RAM 256KB, BLE 5)
- 개발 환경: 아두이노 IDE + 누코드 BSP (Bluefruit BLE 라이브러리 사용 가능)
- 센서: 6축 IMU 모듈 1개를 I2C로 연결 (구체 모델은 미정)
- 배터리: 초기에는 USB 전원

**중요**: NU40 DK의 정확한 핀맵, 온보드 센서 유무, 사용할 IMU 모델을 너는 모른다. **추측해서 지어내지 말 것.** 핀 번호와 I2C 주소, IMU 라이브러리는 파일 상단에 상수와 어댑터 함수로 분리하고, 확인이 필요한 부분은 `// TODO: 확인 필요 —` 주석으로 명시해라. 모르는 API를 그럴듯하게 만들어내는 것보다 TODO로 남기는 게 낫다.

## 이번 범위 (1단계 데모)

한 손 드럼. 스틱을 휘두르면 브라우저에서 드럼 소리가 난다. 여기까지가 이번 목표다.

**포함**
1. 누코드 펌웨어: IMU 샘플링 → 타격 순간 감지 → 세기 계산 → BLE 전송
2. 웹앱: BLE 연결 → 이벤트 수신 → 드럼 소리 재생 → 화면에 타격 표시
3. 실행 방법과 배선을 정리한 README

**제외 (다음 단계)**
- TinyML 분류 모델 (이번엔 단일 드럼 소리만)
- 양손, 기타·베이스 모드, 리듬게임 채보, 녹음

다만 **2단계에서 TinyML 분류를 붙일 자리를 미리 비워두어라.** 펌웨어에는 분류 함수의 인터페이스만 정의해 두고 지금은 고정값을 반환하게 한다.

## 아키텍처

```
[NU40 + IMU]  IMU 100Hz 샘플링
                 → 링버퍼 (직전 0.2초 보관)
                 → 피크 감지 (임계값)
                 → 분류 훅 (2단계용, 지금은 고정값)
                 → BLE notify
        ↓ BLE
[브라우저 웹앱]  Web Bluetooth 수신
                 → Web Audio로 샘플 재생
                 → Canvas로 타격 시각화
```

## BLE 스펙

Nordic UART Service(NUS)를 사용한다. 웹에서 별도 GATT 설계 없이 바로 붙을 수 있다.

- Service: `6e400001-b5a3-f393-e0a9-e50e24dcca9e`
- TX (보드 → 브라우저, notify): `6e400003-b5a3-f393-e0a9-e50e24dcca9e`
- RX (브라우저 → 보드, write): `6e400002-b5a3-f393-e0a9-e50e24dcca9e`
- 광고 이름: `AirBand-R`

**타격 이벤트 패킷 (8바이트, little-endian)**

| 바이트 | 필드 | 값 |
|---|---|---|
| 0 | hand | 0 = 오른손, 1 = 왼손 |
| 1 | mode | 0 = 드럼 |
| 2 | class | 0 = 스네어 (2단계에서 확장) |
| 3 | velocity | 0~127 (MIDI 벨로시티 범위) |
| 4-7 | timestamp | 보드 기준 millis (uint32) |

나중에 MIDI 출력으로 확장하기 쉽게 velocity는 0~127로 맞춘다.

## 펌웨어 요구사항

1. **샘플링**: IMU 가속도 3축을 일정 주기(100Hz 목표)로 읽는다. `delay()` 기반 루프가 아니라 타이머나 경과시간 비교로 주기를 일정하게 유지할 것.
2. **링버퍼**: 직전 0.2초 분량의 샘플을 원형 버퍼에 보관한다. 2단계 분류에서 쓸 데이터다.
3. **피크 감지**: 가속도 크기(3축 벡터 합성)가 임계값을 넘고, 직전 샘플보다 크며, 마지막 타격 이후 불응기(예: 60ms)가 지났을 때만 타격으로 판정한다. 임계값과 불응기는 상단 상수로 분리한다.
4. **세기 계산**: 피크 크기를 0~127로 매핑한다. 매핑 범위도 상수로 둔다.
5. **분류 훅**: `uint8_t classifyHit(const SampleBuffer& buf)` 형태의 함수를 정의하고, 지금은 항상 0을 반환한다. 2단계에서 Edge Impulse 추론으로 교체할 자리다.
6. **BLE 전송**: 위 8바이트 패킷을 notify로 보낸다. **타격 판정과 전송 경로에 블로킹 코드를 넣지 말 것.** 시리얼 출력은 디버그 플래그로 켜고 끌 수 있게 한다.
7. **시리얼 모드**: `#define DEBUG_RAW 1`로 두면 Edge Impulse Data Forwarder가 읽을 수 있는 CSV 형식(`ax,ay,az`)으로 시리얼에 출력하는 모드를 함께 제공한다. 2단계 데이터 수집에 쓴다.

## 웹앱 요구사항

**스택**: TypeScript + Vite. 프레임워크 없이 순수 TS + Canvas. 빌드 후 정적 호스팅 가능해야 한다.

1. **연결**: "센서 연결" 버튼 → `navigator.bluetooth.requestDevice`로 `AirBand-R` 연결 → notify 구독. 연결 상태와 배터리 없는 경우의 표시를 UI에 보여준다.
2. **오디오**: 드럼 샘플을 **앱 시작 시 전부 `decodeAudioData`로 AudioBuffer에 미리 올려둔다.** 이벤트가 오면 `AudioBufferSourceNode` 생성 후 즉시 재생만 한다. 이벤트마다 파일을 fetch하거나 디코딩하면 안 된다.
   - 샘플 파일이 없으면 Web Audio 오실레이터와 노이즈로 간단한 드럼 소리를 합성해서 쓴다 (외부 에셋 의존 없이 바로 돌아가게).
3. **벨로시티 반영**: 패킷의 velocity를 GainNode 볼륨에 반영한다.
4. **시각화**: Canvas에 타격이 들어올 때마다 원이 퍼지는 간단한 이펙트. 화면 하단에 최근 이벤트 로그(시각, 세기)를 표시한다.
5. **지연 측정**: 수신 시각과 재생 시각 차이를 화면에 ms로 표시한다. 튜닝에 필요하다.
6. **HTTPS 안내**: Web Bluetooth는 HTTPS 또는 localhost에서만 동작한다. README에 명시하고, 지원하지 않는 브라우저(iOS Safari 등)에서는 안내 메시지를 띄운다.

## 완료 기준

1. 펌웨어를 올리고 스틱을 휘두르면 시리얼에 타격 로그가 찍힌다.
2. 브라우저에서 센서를 연결하고 휘두르면 드럼 소리가 난다.
3. 세게 치면 크게, 약하게 치면 작게 난다.
4. 걷거나 손을 가만히 들고 있을 때 오작동하지 않는다 (불응기와 임계값으로).
5. 화면에 지연시간이 표시되고, 타격 이펙트가 보인다.

## 작업 방식

- 파일을 실제로 생성해라. 설명만 하지 말 것.
- 확실하지 않은 API나 핀맵은 지어내지 말고 `// TODO: 확인 필요` 주석과 함께 상수로 분리해라. 모르는 건 모른다고 말해라.
- 코드에는 한국어 주석을 달아라.
- 다 만든 뒤에 **지금 상태에서 내가 확인해야 할 것**(IMU 모델, 핀 번호 등)을 목록으로 정리해서 알려줘라.
- 시작하기 전에 꼭 물어봐야 할 게 있으면 한 번에 모아서 질문하고, 없으면 바로 만들기 시작해라.
